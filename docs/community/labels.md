# Suggested GitHub labels

Not applied remotely in this iteration.

| Label | Use |
| --- | --- |
| `area:protocol`, `area:simulation`, `area:network` | Application/network work |
| `area:hardware`, `area:mobile`, `area:infrastructure` | Product roles |
| `area:security`, `area:privacy`, `area:regulatory` | Review disciplines |
| `area:docs`, `area:community`, `area:licensing` | Foundation work |
| `type:bug`, `type:feature`, `type:research` | Nature of contribution |
| `priority:gate`, `priority:next`, `priority:later` | Experiment dependency order |
| `status:needs-evidence`, `status:ready`, `status:blocked` | Readiness |
| `good first issue`, `help wanted` | Bounded tasks with documented support |

Use one primary area and one type; keep labels sparse. A regulatory/legal gate
is not automatically a good first issue. Labels do not imply hardware approval.
